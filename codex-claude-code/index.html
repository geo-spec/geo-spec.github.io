Codex и Claude Code

TL;DR за 30 секунд

  • Codex и Claude Code в 2026 году не конкуренты по принципу «выбери один». Это два слоя одного стека.
  • Самый частый паттерн у практиков: Claude Code ведёт сложные 20% - архитектура, многофайловый рефакторинг, дебаг с диалогом. Codex молотит рутинные 80% - создаёт каркас фичи, закрывает типовые тикеты - и работает вторым, скептическим ревьюером.
  • OpenAI выпустила официальный плагин Codex прямо внутрь Claude Code. Сигнал: вендоры сами признали, что люди их комбинируют.
  • Комбинируй, когда задача большая, неоднородная или важная. Не комбинируй на мелочи - оверхед на координацию съест выигрыш.

Профиль инструментов: на чём каждый реально силён

Бенчмарки меняются каждый месяц. Свойства инструментов - нет. Поэтому здесь опора на устойчивые характеристики, а не на то, кто сегодня на полпроцента выше в SWE-bench.

Ментальная модель: не «кто лучше», а «кто на каком слое»

Ключ - не выбрать лучшего агента, а маршрутизировать работу туда, где она дешевле и качественнее.

6 паттернов комбинирования

Каждый паттерн - отдельный сценарий с понятным условием применения. Бери то, что подходит к задаче, а не всё сразу.

1

Planner → Implementer → Reviewer (правило 80/20)

Самый ходовой сценарий у команд. Claude Code проектирует и ревьюит важные 20%: архитектуру, контракты API, спорные места. Codex делает рутинные 80%: создаёт каркас фичи, пишет типовые заготовки, закрывает понятные тикеты. Общий якорь - файл вроде PROJECT_CONTEXT.md: после крупных изменений он обновляется, чтобы оба инструмента видели одну картину.

Когда брать: фича среднего и большого размера, где есть и «подумать», и «натаскать кода».
2

Cross-review: код одного проверяет другой

Самый недооценённый и самый дешёвый по соотношению польза/усилия. OpenAI выпустила официальный плагин Codex для Claude Code (codex@openai-codex, репозиторий openai/codex-plugin-cc). Три команды прямо из сессии Claude Code:

  • /codex:review - обычное ревью силами Codex (read-only).
  • /codex:adversarial-review - скептическое, состязательное ревью: Codex считает код сломанным и ищет дыры - гонки, потеря данных, откаты, аутентификация.
  • /codex:rescue - передача задачи Codex целиком (единственная команда с правом менять код).

Смысл - поймать то, что одна модель «залюбила» и не видит. Две модели редко ошибаются одинаково.

Когда брать: всегда, когда цена ошибки выше пары минут.
3

Rescue: разблокировка, когда застрял

Документированный практиками сценарий (разбор Nate Herk, 30k+ просмотров): застрял в Claude Code на проблеме - передаёшь её Codex, не меняя контекст и проект, side-by-side. Часто помогает обратное: Codex встал - отдаёшь Claude Code на диалоговый дебаг.

Когда брать: один агент крутится в цикле и не сходится. Смена движка часто разрывает залипание лучше, чем десятый перезапуск того же.
4

Параллельные агенты в git worktree

Запускаешь Claude Code, Codex (и при желании Gemini) бок о бок, каждый в своём git worktree - отдельная ветка и рабочая папка, общий объектный стор. Файлы не сталкиваются. Есть готовые обвязки: johannesjo/parallel-code, desktop-app Runner («запускать как crew»).

Два режима: гонка - одна задача, три агента, сравниваешь диффы, мёржишь лучшее. Веер - пять фич, пять агентов одновременно, ноль конфликтов.

Важное различие изоляции: worktree Claude Code работает локально с полным доступом к инструментам и credentials; sandbox Codex - в облачном контейнере без сети. Поэтому untrusted-код и чувствительное исполнение безопаснее гнать через Codex, а задачи, которым нужен локальный build/test/сервис - через Claude Code.

Когда брать: несколько независимых задач разом, или одна важная задача, где хочешь выбрать из вариантов.
5

Локальный Claude Code + облачный Codex async

Claude Code интерактивно разбирает проблему здесь и сейчас. Долгие ресурсоёмкие вещи - массовая миграция по сервисам, длинный прогон тестов - уходят в облачный Codex как асинхронный PR в отдельном контейнере, пока идёт другая работа.

Когда брать (все три условия сразу): задача блокирует терминал дольше 15-20 минут; scope чётко ограничен; в репо есть надёжные CI-тесты, которые поймают брак.
6

Git как канал связи между агентами

Свежий приём с Hacker News: Claude Code и Codex ведут «разговор» через git - один пишет коммиты и заметки, другой читает и отвечает своими коммитами. Грубовато, но работает без специальной шины: общая история репозитория и есть протокол.

Когда брать: хочешь связать двух агентов без отдельного оркестратора, на том, что уже есть.

Когда НЕ комбинировать

Мелкая правка в один-два файла

Поднимать два агента, синхронизировать контекст и читать два диффа дольше, чем сделать самому. Оверхед координации съест выигрыш.

Нет общего якоря контекста

Без PROJECT_CONTEXT.md / AGENTS.md / CLAUDE.md два агента разойдутся в разные стороны.

Нет тестов под автономную задачу

Agentный прогон без CI-сетки - незаметный брак, который всплывёт позже. Сначала тесты, потом делегирование.

Погоня за бенчмарком

Лидер SWE-bench меняется каждый месяц и почти не влияет на ежедневную пользу. Выбирай по свойствам и цене, не по полпроцента в таблице.

Быстрый старт: минимум, чтобы начать

1
Поставь оба локально: Claude Code и Codex CLI (npm install -g @openai/codex).
2
Один якорь контекста на репо. Заведи CLAUDE.md для Claude Code и @AGENTS.md-импорт для совместимости с Codex. Держи их короткими - это конфиг, а не документация.
3
Подключи cross-review. В Claude Code: /plugin marketplace add openai/codex-plugin-cc, затем /plugin install codex@openai-codex, /reload-plugins, /codex:setup. Нужна подписка ChatGPT или ключ OpenAI API + Node.js 18.18+. Получишь /codex:review и /codex:adversarial-review прямо из сессии.
4
Заведи привычку второго мнения на критичных диффах: писал Claude Code - проверь Codex, и наоборот.
5
Для параллельной работы возьми готовую обвязку worktree (parallel-code или аналог), не городи руками.

Спорные места

Где не надо переоценивать данные - вердикты из базы знаний с уровнями уверенности.

«Codex объективно лучше для архитектуры» - подтверждён лишь паттерн «blueprint Codex → реализация Claude Code». Прямых авторитетных бенчмарков по архитектуре нет. Вердикт: Отчасти верно, уверенность низкая.

«Claude строже следует инструкциям» - да, по CLAUDE.md следует строго, но frontier-модели склонны к over-engineering, а свежие GPT-5.x часто аккуратнее держат жёсткое ТЗ. Не абсолют. Вердикт: Отчасти верно, уверенность низкая.

Бенчмарки SWE-bench у Opus и GPT-5.x-Codex идут вплотную (паритет около 80%) и обгоняют друг друга от релиза к релизу. Это аргумент в пользу комбинации, а не выбора одного навсегда.
